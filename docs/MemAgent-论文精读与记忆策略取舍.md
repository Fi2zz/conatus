# MemAgent 论文精读与记忆策略取舍

- 论文：[MemAgent: Learning to Manage Heterogeneous Memory Providers for LLM Agents](https://arxiv.org/abs/2609.32521)
- 作者：Yongxian Wei、Yilin Zhao、Runxi Cheng、Xinrui Chen、Chun Yuan、Yaoru Wang、Jiahong Yan、Dian Li（清华大学 / 腾讯）
- 状态：arXiv v1（2026-09-26），cs.AI，未经同行评审；代码 `github.com/WalkerWorldPeace/MemAgent`
- 注意重名：与 ICLR 2026 的 *Memagent: reshaping long-context LLM with multi-conv RL-based memory agent*（Yu et al.）不是同一篇
- 本文用途：为 `conatus_memory`（记忆写入策略能力）提供证据与取舍依据；对应设计见
  `docs/superpowers/specs/2026-10-23-memory-write-policy-design.md`

## 1. 一句话与论证链

**不发明新的记忆表示，而是把「该用哪种记忆」建模成可学习的路由问题。**

论证链：13 种记忆方法在 3 个基准上横评 → 没有任何一种跨基准称王 → 后验 Oracle
比最好的单方法高 18.6pp → 所以记忆是「选 provider」问题 → 三阶段路由 + 合成监督
→ 平均 +10.0%（对无记忆基线），且步数减少 12%。

## 2. 问题形式化

任务智能体 `A_T` 跑轨迹 `ξ_τ = (s_0,a_0,o_0,…,s_T,a_T)`，得到二值结果 `y_τ`。
记忆智能体 `A_M` 在三个节点决策：

| 阶段 | 决策 | 上下文 | 动作 |
|------|------|--------|------|
| Begin | 从 K 个 provider 选 1 个检索 | 任务 + 全部 provider 的 probe 预览（去分数、打乱） | 13 选 1（**不可弃权**） |
| In | 是否注入短期工作记忆 | 任务 + 步号 + STM 摘要 + 最近动作 | `query` / `no_op` |
| End | 哪些 provider 写入轨迹 | 结果 + 轨迹摘要 + 带 outcome gate 的 provider 描述 | 任意子集（可空） |

## 3. 方法要点

### 3.1 Provider 池（13 家）

统一接口只有 `retrieve` / `store` 两个操作。实现层面刻意控制变量：

- 11 家共享同一个 384 维 `all-MiniLM-L6-v2`（GPU 锁单例），差异只在表示与索引策略；
- 只有 4 家在**检索路径**调 LLM（Agent-KB / LightWeight / Generative / Cheatsheet）；
- **全部 13 家在存储时调 LLM**（存储贵、检索便宜，靠复用摊薄）；
- probe 阶段全部走 embedding / keyword，绕过 LLM——这是 75ms 能成立的前提。

按「可索引单元」分三族，失败模式互补：

| 家族 | 成员 | 可索引单元 | 典型失败 |
|------|------|------------|----------|
| 相似度检索 | Voyager、DILU、Generative、Cheatsheet | 轨迹 / 查询嵌入 | 表面改写但约束变了；跨域同构检索不到 |
| 结构抽象 | AWM、SkillWeaver、Memp | 工作流模板 / 可执行函数 / 过程脚本 | 过度泛化、覆盖不足、只学成功轨迹所以没有警告 |
| 洞见累积 | ExpeL、Agent-KB、InsightGraph、Mobile-E、EvolveR、LightWeight | 原子洞见 | 词法泛洪、关键词脆弱、剪枝删掉负例、图 hub 劫持 |

### 3.2 Begin：内容感知 probe（全文最有价值的机制）

先用轻量检索拿到每家「当前任务下实际能返回什么」的片段，再让路由器选。两条细节：

- **只给内容、不给分数**；
- 候选随机打乱。

实测：保留分数时 **51.8%** 的选择集中在 2 家；去掉分数后分布均匀且准确率不降。
消融里「保留分数」在 GAIA 上掉 **6.7pp**。

含义：**路由器的输入应是候选的真实产出，而不是候选的自评分。**

### 3.3 In：规则抽取 + 二分类门

STM 完全规则化、零 LLM：

| 结构 | 容量 | 显示门槛 |
|------|------|----------|
| Verified facts | 15（每步最多 3 条） | ≥2 条 |
| URL history | 30 | ≥3 条 |
| Search history | 20 | ≥4 条 |

三个可复用工程细节：Jaccard > 0.6 去重；14 条正则做错误分类且**只扫 observation
前 500 字符**；保守显示（三段全低于门槛就返回空串，超预算在 section 边界截断）。

门控行为：1102 次 In 决策中 Query 率 **30.4%**；Step 0 恒为 NoOp；Steps 5–6 升到
**55–71%** 后回落。

### 3.4 End：选择性存储（对 conatus 最直接）

写入时按 provider 的 outcome gate 分流：成功时存 3–8 家（混选 all-outcomes 与
success-only），失败时只存 all-outcomes 家。消融：全量存 65.5 → 选择性存 **69.7**。

### 3.5 训练数据合成

没有标签，于是：

1. **强制探索**：对 173 条训练任务（53 条 GAIA L1 + 120 条 TaskCraft），遍历
   `13 provider × {Query, NoOp}`，只覆盖记忆路由、不动任务智能体。
2. **三类奖励**：
   - 任务正确率（Begin）：`P⁺` 为真非空子集时判别力最强；`P⁺ = P` 只按 judge
     取 top-k；`P⁺ = ∅` 整条丢弃。
   - LLM-as-Judge 归因（Begin/In）：0–5 分 × 6 档 rubric，维度加权到 `[0,1]`。
   - 下游复用（End）：`r_end = ½·min(1, |T_{>τ}|/H) + ½·(下游成功数/|T_{>τ}|)`，
     `H = 5`——存储的价值只由「后来真的被检索到并帮到别的任务」定义。
3. 奖励过滤 + LoRA SFT（只对决策 token 算 loss）。

### 3.6 InsightGraph（作者自研 provider）

- 图：typed KG；节点 = 成功轨迹抽的 2–4 条 ≤30 词洞见；same-task 边 `w=1.0`；
  similar-concept 边在 `cos ≥ 0.55` 时建立，初始权重 = 相似度。
- 检索：`s = 0.2·TFIDF + 0.8·cos`，top-5 种子；单跳扩展 `γ = 0.7`、每种子 ≤3 邻居；
  阈值 `0.22`；top-3 拼接、500 字符上限。
- 自适应边权：`w_eff = α·w₀ + (1-α)·(k+1)/(n+2)`，`α = 1/(1+n/κ)`，`κ = 5`；
  Laplace 平滑的 Beta(1,1) 后验，冷启动保护 + 经验纠偏；`n ≥ 2` 才更新，clamp 到
  `[0.1, 1.0]`。
- 巩固：每 50 个任务合并 `cos ≥ 0.85` 的节点，剪掉 `n ≥ 5 且成功率 < 20%` 的边。

## 4. 实验数据

### 4.1 主表（准确率 %）

| 方法 | GAIA | WebWalkerQA | xBench-DS | 平均 |
|------|------|-------------|-----------|------|
| 无记忆 | 58.8 | 69.4 | 69.0 | 65.7 |
| 最好的单 provider | 64.8（AWM） | 77.1（ExpeL） | 77.0（SkillWeaver） | 71.0 |
| All-Concat | 62.4 | 74.1 | 73.0 | 69.8 |
| All-Fuse | 63.6 | 75.3 | 74.0 | 71.0 |
| **MemAgent** | **69.7** | **79.4** | **78.0** | **75.7** |
| Oracle | 87.3 | 89.4 | 92.0 | 89.6 |

三个基准线必须分清：

- vs 无记忆：**+10.0pp**（摘要里的数字）；
- vs 最强单 provider：+4.9 / +2.3 / **+1.0**，平均 **+4.7**；
- vs Oracle：只回收 **25.3%** 的差距（GAIA 21.8%、WebWalker 18.7%、xBench **6.7%**）。

`All-Fuse` 平均恰好等于最强单 provider，说明「多源堆上下文」本身不涨分，这是
「路由必要性」的最强证据。

### 4.2 消融

训练管线（GAIA）：Base 60.6 → 去掉 Begin 正确率过滤 62.4（**+7.3**）→ 保留 probe
分数 63.0（**+6.7**）→ 去掉 In 阈值过滤 63.6（+6.1）→ 去掉 End 下游奖励 66.7
（+3.0）→ 完整 **69.7**。

推理架构：全无 58.8 → 仅 In 63.0（+4.2）→ Begin+In+全存 65.5（+6.7）→ 选择性存
69.7（**+11.0**）。

### 4.3 路由行为

- Begin：Memp 22.6% / DILU 19.0% / Mobile-E 16.7% / ExpeL 16.7%；13 家全部被选过。
  **GAIA 上最强的 AWM 并不是被路由最多的**——学到的是按内容选，不是按平均战绩选。
- 5-provider 变体（人工挑的「互补集」）平均 69.8，比 13 家少 **5.9pp**：多样性值钱，
  人工判断互补性不可靠。
- 容量：4B 69.7 → 9B 70.9（+1.2）；**未训练**的 4B/9B 都是 63.6——监督信号远比
  路由器参数量重要。
- PromptRoute（免训练，GPT-5-mini + 决策知识库）平均 70.9 = 训练版的 **93.7%**。
  大部分收益来自信息结构，而不是 SFT。

### 4.4 开销

Begin 注入 ~369 tokens（中位 268，max 2.2K）；In ~210 tokens/次、平均 3.8 次；
合计 ~1.2K（<0.5% 任务 token）。probe ~75ms、4B 推理 ~80ms/决策、总路由 ~1.2s/任务
（<0.3%）。平均步数 9.1 → **8.0（−12%）**，注入量低于 Agent-KB（419）与 ExpeL（971）。

### 4.5 失败分解与任务覆盖

GAIA 失败归因：覆盖天花板 **42%** / 路由错误 **24%** / 记忆质量 **20%** /
检索干扰 **14%**。

| 被几个方法解出 | GAIA | WebWalker | xBench |
|----------------|------|-----------|--------|
| 0（不可解） | 12.7% | 10.6% | 6.0% |
| 1–2（路由关键） | **12.1%** | 6.5% | 8.0% |
| 7–13 | 28.5% | 23.5% | 44.0% |
| 14（全解，免费） | 35.2% | 51.2% | 35.0% |

**路由只在 8–12% 的任务上真正决定成败**，35–51% 是「免费」的。任何路由论文的
headline gain 都会被这层稀释；也解释了 xBench 为何只有 +1.0。

## 5. 批判性评估

### 站得住

1. 「无单一记忆表示通吃」——13×3 横评 + 10/13 至少独解一题。
2. probe 去分数——行为数据（51.8% 集中度）+ 消融（6.7pp）双重支撑。
3. 选择性存储 > 全量存储——+4.2pp，且与 14% 检索干扰互证。
4. 监督信号比模型容量重要——4B→9B 仅 +1.2，未训练时同分。
5. 效率收益真实——−12% 步数、注入 token 低于多数单方法。

### 站不太住

1. **没有方差 / 多种子 / 置信区间**；xBench 的 +1.0、WebWalker 的 +2.3 大概率在
   噪声内。方向可信，幅度不可信。
2. **「判定模型与任务智能体完全独立」不成立**：任务智能体是 GPT-5-mini，
   GAIA / WebWalkerQA 的正确性判定**也是** GPT-5-mini。
3. GAIA L1（53/165）既灌记忆库又用于评估下游复用，不是严格留出集。
4. 训练集仅 173 条，且「全成功」任务占 GAIA 35%，判别性样本可能只有几百到一千条，
   过滤后样本数未报告。
5. 摘要主打 **+10.0% vs 无记忆**；真正竞品是「固定选一个 provider」（71.0），
   对应只有 **+4.7**。
6. 关键超参（`τ_sim=0.55`、`γ=0.7`、`τ_min=0.22`、`κ=5`、`H=5`）全部拍定，无敏感性分析。
7. 自研的 InsightGraph + STM 也在池内，缺「移除自研 provider」的消融。
8. 强制探索（约 4500 条轨迹 × 每家存储调 LLM）的成本完全未报。

### 不能下的结论

- 路由是通用解：只在 web / deep-research 任务、固定 Flash-Searcher + 4 工具上验证。
- SFT 优于 prompt：PromptRoute 用的是冻结通用大模型且未调优，与 4B 微调不可比。
- InsightGraph 有用：单独平均 69.7，无移除消融，入池理由是多样性而非更强。

## 6. 对本项目的适用性

### 已落地（`conatus_memory`）

- **End 选择性写入**：空回复 / 寒暄 / 短回复 / 近重复不写，超长截断。这是论文里
  「写入过滤 +7.3」「选择性存 +4.2」两条最强消融的直接对应。
- **能力化接入**：不塞进 `agent` 或 `foundation`，经 `AgentLoop.addTurnTracker`
  多播挂载；`agent` 只保留通用生命周期钩子。
- **探针工具** `tool/memory_probe.dart`：在真实数据上量化关键词召回的 MISS 率与
  注入成本，作为后续任何检索改动的判定依据。

### 值得后续借鉴

- **Begin 阈值 + 弃权**：论文 14% 的失败来自强制注入，而它自己的 Begin 没有
  弃权选项——不要抄这个缺口。
- **覆盖度评测协议**（§4.5）：在投入记忆优化前，先测自家任务里「路由关键」占比。
- **条目级 `(n,k)` 排序**：把 InsightGraph 的 Beta 平滑平移到 `MemoryEntry`，
  替换 `createdAt` 平局规则。

### 不适用于本项目

| 论文做法 | 不用的原因 |
|----------|------------|
| SFT 一个 4B 路由器 | conatus 是库，用户不该继承微调模型；PromptRoute 已拿到 93.7% |
| 完整 InsightGraph | 图存储 + 巩固任务 + 4 个超参，与「200 行零依赖」的内存机制不匹配 |
| 13 个 provider 清单 | 当词汇表用，不当 roadmap |
| embedding 语义召回 | 当前语料 1–3 条/项目；判定 MISS 率 ±10pp 需 ~81 次查询，检测 1pp 端到端收益需 ~33k 任务/组 |

## 7. 关键公式速查

- Begin 奖励判别集：`P⁺_τ = {p : y_τ^(p,·) = 1}`
- 归因奖励：`r_d = ⟨w^(φ), ŝ⟩`，`ŝ_i = s_i/s_max` 或 `1 - s_i/s_max`（反向维度）
- 下游存储奖励：`r_end = ½·min(1, |T_{>τ}|/H) + ½·(成功下游数 / |T_{>τ}|)`
- InsightGraph 种子：`s(v,q) = 0.2·cos(TFIDF) + 0.8·cos(emb)`
- 图扩展：`s(u,q) ← max(s(u,q), s(v,q)·w_eff·γ)`
- 自适应边权：`w_eff = α·w₀ + (1-α)·(k+1)/(n+2)`，`α = 1/(1+n/κ)`
