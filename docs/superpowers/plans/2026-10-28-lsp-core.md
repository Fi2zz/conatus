# LSP Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a disabled-by-default LSP client to nava that starts configured stdio language servers, exposes diagnostics to the model, and appends diagnostics after file edits.

**Architecture:** A config layer describes servers by extension. A minimal JSON-RPC stdio client owns one server process. A manager routes file paths to servers, keeps diagnostics, and restarts on demand. A read-only `lsp_diagnostics` tool plus an edit-result middleware expose diagnostics without making edits depend on LSP availability.

**Tech Stack:** Dart 3.11, `dart:io` process/stdio, `dart:convert` JSON, existing `Tool`/`ToolRegistry` seams, `package:test`.

**Spec:** `docs/superpowers/specs/2026-10-28-nava-opencode-parity-roadmap.md` (P0 section)

## Global Constraints

- LSP is disabled by default; an absent/empty LSP config must produce zero processes and zero tools.
- Servers are configured explicitly with `command = [...]`; never invoke through a shell.
- LSP failures are fail-open: diagnostics are optional, file edits still succeed.
- Server start timeout 5s; individual request timeout 10s; diagnostics wait 2s.
- Diagnostics output is bounded (20 entries / 4000 chars).
- Do not add a third-party LSP client dependency; implement the small subset needed here.
- Do not install language servers automatically.
- Do not expose LSP commands as model-callable tools.
- Existing `dart analyze` and full test suite must stay green.

## Review Focus

- An edit must never be reported as failed because an LSP server crashed, timed out, or returned no diagnostics.
- A server must be killed on context disposal, TUI exit, and restart; no orphan processes.
- A file with no configured extension must not start any server.
- Malformed JSON-RPC frames, missing Content-Length, and partial stdout chunks must not crash the TUI.
- Starting from a worktree/subdirectory must initialize LSP with the worktree root and use absolute `file://` URIs.

**Interfaces:**
```dart
enum LspSeverity { error, warning, information, hint }

class LspDiagnostic {
  const LspDiagnostic({
    required this.path,
    required this.line,
    required this.column,
    required this.severity,
    required this.message,
    this.code,
  });

  final String path;    // 1-based line/column in display
  final int line;
  final int column;
  final LspSeverity severity;
  final String message;
  final String? code;
}

class LspClient {
  LspClient({
    required List<String> command,
    required String workdir,
    Map<String, String> env = const <String, String>{},
    Map<String, Object?> initialization = const <String, Object?>{},
    Duration startTimeout = const Duration(seconds: 5),
    Duration requestTimeout = const Duration(seconds: 10),
    Duration diagnosticsWait = const Duration(seconds: 2),
  });

  Future<void> start();
  Future<List<LspDiagnostic>> diagnose(String path, {String? text});
  Future<void> stop();
}
```

- `start()` spawns `Process.start(command[0], command.skip(1), workingDirectory: workdir, environment: {...env})`.
- Implement Content-Length framing; stdout may arrive in partial chunks. Drain stderr into a bounded string for errors.
- `initialize` params: `processId`, `rootUri`, `capabilities: {}`, `workspaceFolders`.
- Handle server `workspace/configuration` requests by replying with `[null, ...]`.
- `diagnose` sends `didOpen` once per path and `didChange` afterwards, using full-text sync; returns diagnostics from `textDocument/publishDiagnostics` matching the URI, waiting up to `diagnosticsWait`.
- On `stop`: send `shutdown` (ignore errors), `exit`, wait 1s, kill if still alive.
- Malformed frame → return empty diagnostics, do not throw out of `diagnose`; `start` may throw a typed error.

### Task 3: LSP manager and extension routing

**Files:**
- Create: `packages/conatus_code/lib/src/lsp/lsp_manager.dart`
- Create: `packages/conatus_code/test/lsp/lsp_manager_test.dart`

**Interfaces:**
```dart
class LspServerStatus {
  const LspServerStatus({
    required this.name,
    required this.state,
    this.error,
    this.diagnosticCount = 0,
  });

  final String name;
  final String state; // disabled / idle / running / error
  final String? error;
  final int diagnosticCount;
}

class LspManager {
  LspManager({
    required LspConfig config,
    required String workdir,
    LspClient Function(LspServerConfig server)? clientFactory,
  });

  Future<List<LspDiagnostic>> diagnose(String path);
  Future<List<LspDiagnostic>> fileChanged(String path);
  List<LspServerStatus> statuses();
  Future<void> restart([String? name]);
  Future<void> close();
}
```

- If `config.enabled` is false or no server matches the extension, return `[]` without starting processes.
- One client per server name, started lazily on first matching `diagnose`/`fileChanged`.
- If a client fails to start, mark state `error`, return `[]`; next call may retry once after a restart.
- `fileChanged(path)` calls `diagnose` with fresh file text (read only if path exists).
- `restart(name)` stops and removes a client; next diagnose restarts it.
- `close()` stops every client; idempotent.
