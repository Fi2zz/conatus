# 人机双写：一种基于补丁的 Agent 协同范式

> 设计文档 · 基于 conatus（Dart）架构讨论整理
> 状态：设计推演完成，未实现
> 核心三句话：**预设即策略，补丁即故事，内核即机制。**

---

## 1. 背景与范式主张

聊天范式把「对话记录」当作产品本体：人发消息、模型回复、历史滚动。这个范式有三个结构性缺陷：

- 反馈靠语言。纠正 AI 必须「说清楚哪里不对」，意图传递有损且易解析歪。
- 过程即黑箱。用户看不到模型在每一轮实际看到了什么，行为不可审计。
- 历史只能追加。说错的话、走错的方向无法回溯，只能继续往下盖。

本文档提出另一种范式——**人机双写**：

1. **LLM 聊天整体作为一种流产物**：聊天不是产品本体，LLM 的输出流是流入文档的原材料，**文档才是 artifact**。
2. **协同编辑作为 agent 的交互**：agent 不通过对话框说话，通过对文档的编辑说话——提议、修改、批注。
3. **每个会话就是编辑你和 AI 的故事**：会话历史本身即文档，回溯即翻故事，分叉即开支线。

两个作者（人、AI），一种原语（补丁），一个 artifact（故事）。

## 2. 核心原理

### 2.1 补丁是一等公民，状态是派生物

文档不存储状态，存储补丁序列；任何时刻的状态都是「截至该时刻生效的补丁集」折叠（fold）出的视图：

```
state(t) = fold(effective(patches)[0..t])
```

`effective` 指应用 supersede 规则后的生效集（见 §4.4：序列只追加，被 supersede 的补丁不再生效）——因此 fold 的不是字面 `patches[0..t]`，而是截至 t 仍在生效的那些补丁。

- **traveling** 不是搬动状态，是在序列区间 [0, T] 里移动游标 t。
- **改状态** 是修改区间里的补丁（或登记 supersede 补丁），重新 fold。
- 存储只有一份补丁序列，所有「时刻」都是它的派生视图。

先例：Vim 的 undo branches 与 Emacs 的 undo-tree 包（编辑分支树上的区间游走）、Pijul（patch 理论的 VCS）、Automerge/ProseMirror（文档 op 日志的工程可行性）。AI 作为第二作者不改变数学，只改变补丁的体量与来源。

### 2.2 effect scope 即补丁

在 conatus 中，这个映射近乎天然：**AI 的每次编辑是一个 effect scope**，scope 自带「应用 / 回滚」双向语义，就是一个补丁。推到底：

**文档树 = 已提交 scope 序列的 fold 结果。** 与 [Cordis](https://github.com/cordiverse/cordis) 范式同构：context tree 是依赖解析的派生物，文档状态是补丁历史的派生物，均不独立存在。

由此，范式中的所有交互统一为补丁级操作，没有特例：

| 交互 | 补丁语义 |
|---|---|
| AI 流式产出 | 生成一个补丁（pending scope） |
| 人接受 | 提交 scope |
| 人拒绝 | dispose scope |
| 人直接改 AI 的结果 | 人打一个补丁，supersede AI 补丁的相应部分 |
| 锚点批注提问 | 锚定在某补丁上的批注补丁 |
| 回溯 | 移动游标 / 分叉 |
| 改 system prompt | 修改策略层预设补丁 |

### 2.3 文档层与过程层分离

「不看 thinking，只留结果」要拆成两层：

- **展示层不保留**：文档里只有结果。与人 pair programming 不需要对方内心独白，只需要 diff。thinking 只是产生那次编辑的临时计算。
- **过程层弱保留**：session-log 仍记录 thinking，但打 transient 标记——文档不可见，上下文紧张时最先被压缩驱逐（类比 `tool_result_eviction` 与 layered compaction 两个模式；thinking 专属的 transient 驱逐是新机制），replay 调试时仍在。文档侧成本为零（log 体积的代价见 §5 边界声明）。

由此模型获得一个健康性质：**模型的「记忆」完全由文档承担**，人与 AI 共享唯一事实源，而不是各自保留一份对聊天的不同记忆。

一句话：故事只写结果，草稿纸留着但随时可被收走。

### 2.4 diff 即反馈

聊天范式里，纠正靠语言（有损）；文档范式里，**直接修改本身就是无歧义的反馈**——比任何文字解释精确，与 Git 同构：AI 提交 commit，人 amend，AI 看 diff 即明白一切。

落地需要两个机制：

1. **人的编辑是一等事件**：人的每次修改作为 op 进入 session-log（当前 log 只记 agent 侧）。模型下一轮注入的不是「用户说……」而是「自你上次编辑后，文档发生这些变化」。实现为一个流服务（与 timer/logger 同模式），谁订阅谁 inject。于是「只改不提问题」也成立——AI 从 diff 里读偏好。
2. **锚点批注作为轻量提问**：批注锚在块上（类 GDocs 评论），即带位置的 ask_user；问题有锚点，回答可精确落在对应块。

### 2.5 会话即故事

session-log（JSONL、fork/replay 为现有能力；「模型可见性不变量」是本范式新引入的约束，见 §5）在新范式中从内部状态提升为一等 artifact：

- 会话 = 文档；fork = 故事支线；replay = 重读。
- log 只追加，任何时刻的完整上下文（含 prompt、工具返回、thinking）都在故事内——见 §5 透明性。

## 3. 交互语义：一轮协同的完整流程

```
AI 流式产出编辑
  → 编译为文档 op 流（插入/替换/移动 block）
  → 注册为 pending effect scope（UI 呈现为改动块，作者=AI）

人：
  ├─ 接受        → 提交 scope
  ├─ 拒绝        → dispose
  ├─ 直接改      → scope 按块收缩（编辑即裁剪），
  │                人的改动作为 diff 事件进 log
  └─ 锚点批注    → ask_user 落在块上

AI 下一轮注入：文档快照 + 未决建议 + 自我上次以来的 diff
thinking：transient，不进文档，上下文紧张先驱逐
```

**待定建议内直接改的语义（编辑即裁剪）**：人在 pending scope 内改动的块，自动从该 scope 脱离，剩余部分仍可整体接受/拒绝。这要求 effect scope 有身份、能按块追踪归属——是「演示」到「能用」的分水岭。

**AI 何时动手**（三档，建议从 ① 起步）：

1. 回合制：人停笔 / 显式召唤才编辑（编辑锁）。停笔检测做成事件注入 Context。
2. 块级并发：按 block 粒度 last-writer-wins，冲突处留双版本。
3. CRDT：真协同，引外部库或自研 mini-CRDT，工程量最大。

## 4. 时间回溯与区间 traveling

### 4.1 checkout 而非 re-execution

回溯 ≠ 重跑 agent。重跑 LLM 花钱且不确定（同输入未必同输出）。正确模型是 **git checkout 而非 git re-commit**：log 是完整事件流且 LLM 响应记录在案，回溯时**取出**当时状态而非**重演**当时计算。回溯成本 = 读文件的 O（历史长度）。

### 4.2 可逆性分类

「牵扯周边文件」的复杂度来自可逆性差异，在 effect 注册时打可逆性标记（scope 元数据的一个字段）：

| 状态类型 | 例子 | 回溯语义 |
|---|---|---|
| 纯文档内部 | 正文、结构 | 恢复快照，零成本 |
| 可再生的衍生物 | AI 生成的配图、代码文件、渲染产物 | 标记失效，用到时重新生成 |
| 外部可补偿 | 已发出的草稿、已建的定时任务 | 不能撤回，补偿（发修订版/取消） |
| 单向门 | 已付费 API 调用、已发布内容 | 物理不可逆，回溯到此为止 |

前两类是 conatus 原生领地（可逆 effect + LIFO 回滚；「晚注册安全」恰好处理「回溯点之后注册的 effect 要拆」）。第三类把补偿操作注册成 effect 的一部分（Saga 模式进 effect 语义）。第四类引出 4.3。

### 4.3 单向门与提交边界

回溯不承诺无限远。每跨过一个单向门，历史线在门处**线性化**：回溯点不可越过，UI 时间轴显示「到此为止」。这与 git 不能撤回已被拉取的提交、只能 revert 同理。approval 插件已做高风险确认，把「是否单向门」纳入风险评估是顺势一步。

### 4.4 修改补丁 = supersede，序列只追加

语义上「修改 patch 本身」成立；存储上强烈建议 session-log **只追加**：修改一个补丁 = 在序列原位置登记 supersede 它的新补丁，fold 时后者生效。

由此兼得两个性质：

- **故事永不丢东西**：被改掉的 AI 草稿、被回滚的方案全部留在 log——「故事」没有删除键。
- **状态完全可控**：fold 只看当前生效补丁集。

故事的完整性（log 层）与状态的可控性（fold 层）分离，互不拖累。

边界：supersede 只改写文档层的生效视图——被 supersede 的补丁若已触发单向门副作用（§4.3），外部效应不随之撤销，只能走补偿。

### 4.5 依赖图与非 LIFO 回滚

**锚必须稳定**：补丁锚在稳定块 ID 上，不锚偏移量（前面插一个字后面全错位）。

**级联失锚**：补丁 B 修改了补丁 A 创建的块，回滚/修改 A 后 B 失锚。处理（同构于 Pijul 依赖理论）：

- 每个补丁记录依赖的前置补丁集，构成依赖图。
- 回滚 A 时级联检查：依赖 A 的后续补丁标记为**失锚**（UI：悬浮补丁），由人重新锚定、改写或丢弃。不自动猜。
- conatus 现有回滚是注册序 LIFO 的；区间 traveling 需要**非 LIFO** 拆中间补丁——仅当依赖图证明后置补丁不依赖它时才允许。依赖图就是非 LIFO 回滚的安全证明。

### 4.6 检查点与 fold 成本

游标移动若每次从头 fold 太贵：layered compaction 在此变成**检查点**——每隔一段序列存一次折好的快照，游标从最近检查点增量折。traveling 实际成本 = O（到最近检查点的距离）。注意这是提案而非现成能力：compaction 的滚动摘要目前没有「从日志折叠重建」的通路（其 README「限制」明示），检查点化需先补这条路。

**游标的三个操作**：预览（移动 t，只读）、分叉（从 t 起新分支，旧分支保留）、截断（t 之后标记作废）。UI：一条带刻度的滑动轴，刻度是补丁，颜色区分作者。

### 4.7 多文件：工作区视角，两层引擎

- **文档内回溯**：effect scope 树够用，零依赖；画布/编辑器类宿主用它。
- **工作区级回溯**：这一层在 conatus_code 已落地——checkpoint 子系统提供 turn 0 基线 + 每轮差量、keep-N 保留，且每份快照随存 `lastEventId` 关联 session fork 切点（「哪份快照对应哪段故事」的语义层已在）；后端双轨并存：自研 gzip 归档（零外部依赖）与影子 git 仓库。git 工具（`git_status` / `git_diff` / `git_commit` / `git_add` / `git_branch` / `git_stash`）同样在 conatus_code，不在 fs 能力缝。因此本文档要补的是**文档内**粒度，工作区层以现有 checkpoint 为起点；「session-log 事件 ↔ commit/快照」的映射沿用其 `lastEventId` 模式。

参照系：兄弟仓库 conatus_viva（非本仓内容）的 `state.json` + 步骤级幂等 + artifacts 落盘 + dry-run，就是一个仅限前进方向的时间机器（指针拨回 + 删下游产物 + 幂等重跑）。文档侧粒度从「步骤」细到「编辑块」，模型相同。

### 4.8 显式非目标：分支间自动合并

回溯后改另一条线再合回来 = 散文/设计稿语义的冲突，无可靠自动解（代码有 AST 与类型兜底，故事没有）。分支定位为「草稿线」，合并 = 人主导、AI 辅助的三方对照编辑。

## 5. 透明性作为一等设计值

**模型可见性不变量 + log 是一等 artifact = 模型在 t 时刻看到的每一个字都记录在案。** 用户可 checkout 到任意一轮，查看该刻完整上下文装配：system prompt、注入技能、记忆、文档快照、工具返回。AI 的每个行为都可回答「它当时为什么这么做」。

前提声明（墙的提前引用）：本节说的「可改」仅指**策略层**预设；机制层（log 只追加、fold、scope 回滚）不可被会话补丁改动，理由见 §6.1。

连锁反应：**system prompt 自己也是补丁**——

- 查看（透明）：没有一类东西享有「藏在装配过程里」的特权。
- 修改（主权）：不满意口吻或规则，直接在历史里改，后续 fold 生效。
- 分叉（草稿线）：改出两个性格的 agent 线对比。

prompt 工程从开发者的暗手艺变成用户可参与的编辑行为——与开源同构：黑箱对应闭源，可查看可分叉对应开源。故事因此包含动机层面：AI 不只是做了什么事，它为何如此理解你，也在故事内。

**边界（诚实声明）**：

- 可见 ≠ 可复现：t 时刻的搜索结果记录在案但无法重新验证；模型权重仍是最后一个黑箱（可审计输入，不可审计训练）。
- 密钥挡在透明性外：凭证进 log 必须掩码（复用 credentials 插件），否则透明性变成泄露面。原则：对行为有解释力的全透明，对安全有破坏力的全隔离。
- 体积：每轮完整上下文进 log 会膨胀，存每轮的上下文装配**增量**（复用 context-cache 的思路），完整视图靠 fold——注意「从日志折叠重建」的通路目前在 compaction 中尚不存在（其 README 明示的限制），是真实缺口，同 §4.6。

落到 conatus（提案，当前未实现，见 §7.1）：system-prompt 插件应每轮把最终发给模型的完整上下文（掩码后）作为一条 patch 写进 session-log——该插件今天只做段/上下文的注册与装配渲染，无任何 log 写入。补上后与 checkout 语义闭环：traveling 到 t，看得到文档状态，也看得到模型的眼睛。

## 6. 总纲：三层架构

| 层 | 内容 | 性质 |
|---|---|---|
| **策略层** | system prompt、skills、工具声明、MCP 配置、记忆 | 全是文件预设——用户主权、透明、可分叉、皆补丁 |
| **故事层** | 补丁序列（session-log） | 只追加、人机共享、可 traveling、supersede 生效 |
| **机制层** | context tree、effect scope、fold 引擎、approval、装配器 | 小而稳定、开源、**不是预设、不被会话内补丁改动** |

### 6.1 为什么机制层不能也是预设

预设能**声明**能力，不能**实现**能力。「有一个叫 generate_monthly_video 的工具」是预设里的文本；真调万相 API、按秒计费、过 approval、落 artifacts——是代码。文档 fold、supersede、scope 回滚、log 只追加——也是代码。prompt 无法 dispose 一个 effect scope。

用户改策略层的自由，**恰恰以机制层不可被会话改动为前提**：否则一个补丁改掉「log 只追加」，故事完整性塌掉，前述全部承诺（可审计、可 replay、traveling）失效。这是用户主权与系统完整性之间的墙。

### 6.2 「一切回归 prompt」的准确表述

模型可见层：是的。模型眼中本没有 system prompt / MCP / skill / 插件这些类别，只有进上下文的 token；类别是工程概念，不是模型的现实。装配层 = 一套文件预设，`fold(预设) → 发给模型`。

执行层：不行。工具实现、效果回滚、世界副作用留在机制层，通过小而稳定的工具面暴露给策略层。

由此得到 conatus 的产品定位：**conatus 内核 = 机制层，发行版 = 预设包**。写作搭档、健身教练、编程助手 = 不同预设包。同 Linux 发行版逻辑：同一内核，不同预设。插件大部分可逐步蒸发为预设（skill 已经是 markdown 文件），剩下的才是内核必须守的 runtime。

### 6.3 预设供应链风险

预设可分享 = 新的供给面：他人预设包可在文本中重定义工具含义、注入隐秘指令。透明性是弱防线（依赖人查看）。机制层应对工具调用做白名单 / 风险分级，**不信任预设文本的自我声明**。

## 7. conatus 原语映射与待补项

### 7.1 现有原语 ↔ 范式角色

| 现有机制 | 范式角色 |
|---|---|
| effect scope | 补丁（应用/回滚双向语义） |
| session-log（JSONL/fork/replay） | 故事层载体（只追加是现有硬不变式；模型可见性不变量为本范式新增） |
| layered compaction / tool_result_eviction | 检查点与 transient 驱逐的模式参照（均非现成对口，需新实现） |
| approval + 风险分级 | 提交门 / 单向门识别 |
| context-cache | 前缀缓存指纹与命中遥测；「装配增量存取」仅复用其思路 |
| conatus_llm streaming | 补丁的生成流（token 流 → op 流编译管道） |
| ask_user | 锚点批注 |
| coeffect / dirty-mark 重算 | 文档变更 → 在途建议标脏重跑 |
| conatus_code checkpoint（双后端 + `lastEventId` 切点关联）与 git 工具 | 工作区级回溯引擎（已落地） |
| system-prompt 插件 | 策略层装配器（需增加每轮写 log 补丁） |
| credentials 掩码 | 透明性/安全性边界 |

### 7.2 待补的三个小原语（机制层）

1. **scope 身份与按块锚定**：scope 有稳定 ID，补丁锚定块 ID 而非偏移量；支持「人在 pending scope 内编辑 → 按块收缩」。
2. **可逆性标记**：effect 注册时携带可逆性类别（纯文档 / 可再生 / 可补偿 / 单向门），作为回滚引擎与 UI 时间轴的依据。
3. **补丁依赖图**：每个补丁记录前置依赖集，支撑非 LIFO 回滚的安全证明与级联失锚。

外加一处配套改动：人的编辑（事件源在机制层外）作为一等事件写入 session-log（diff 事件流服务，写入动作本身在机制层内）。

### 7.3 显式非目标

- 分支间自动合并（§4.8）。
- 用预设替代机制层（§6.1）。
- 跨单向门的无限回溯（§4.3）。

| 系统 | 与本范式的关系 |
|---|---|
| 聊天范式（ChatGPT/Claude 等） | 对照组：历史只追加、反馈靠语言、prompt 黑箱 |
| Git | 工作区级回溯与 diff 即反馈的语义来源；本范式 = 把 git 语义内化为运行时 |
| Pijul | patch 理论与依赖理论的先例 |
| Vim/Emacs undo-tree | 区间 traveling 的交互先例 |
| Automerge / ProseMirror | 文档 op 日志的工程可行性 |
| CRDT（Yjs 等） | 真并发的可选第三档（§3），非必选 |
| OpenClaw（SOUL.md）/ Claude Code（CLAUDE.md + skills） | 「一切皆文件预设」的同路人；本范式更进一步——预设在故事内、可被会话补丁修改 |
| Google Docs + Gemini | 产品形态相近，但无补丁历史、无 traveling、prompt 黑箱 |
| Saga 模式 | 可补偿 effect 的语义来源 |

---

## 9. 一页总结

> **范式**：文档即会话，编辑即对话，故事即历史。
> **数据模型**：`state(t) = fold(截至 t 生效的补丁集)`；补丁锚定块 ID、携带作者/可逆性/依赖集；序列只追加，修改 = supersede。
> **交互**：AI 产出 = pending scope；接受/拒绝/直接改/锚点批注 = 四种补丁操作；diff 即反馈；人编辑是一等事件。
> **回溯**：checkout 语义（取状态非重跑）；单向门线性化历史；依赖图保证非 LIFO 回滚；compaction 作检查点；分支不做自动合并。
> **透明**：每轮完整上下文（掩码后）进 log；prompt 从配置变补丁，可查看/修改/分叉。
> **架构**：策略层（文件预设，用户主权）/ 故事层（补丁序列，只追加）/ 机制层（conatus 内核，小而稳定，不被会话改动）。
> **产品**：conatus 内核 + 预设发行版；插件逐步蒸发为预设，内核只守机制。
> **待补**：scope 身份与块锚定、可逆性标记、依赖图；外加 diff 事件入 log。
